# Design engineer job description

A design engineer job description should read like a software role. If the requirements are SolidWorks, GD&T, or a cleanroom, it is a different profession. This is an outline for a template teams can post, plus the UX engineer variant people also search for.

## Outline

### Template: software design engineer
- One paragraph on the product and the surface this person owns.
- Outcomes: shipped UI, a prototype practice, a design system contribution.
- Stack, named plainly: React, TypeScript, CSS, Figma, prototyping tools. Add SwiftUI or Framer only if the team uses them.
- Collaboration: design partners, frontend, and how decisions get made.
- Level signals: scope, ambiguity, whether they set the system or implement it.
- Pay: publish the base range. Listings with a range are the ones that can carry salary markup, and they are what the [salary page](/salary) can cite.

### UX engineer job description
- Same bones, with the UX engineer emphasis: prototyping fidelity, design-system APIs, and accessibility.
- What to ask for: a portfolio with working prototypes, not only mockups.
- What to leave out: visual-only case studies as the whole bar, and generic “frontend engineer” leveling with no design judgment.
- Link the live [UX engineer jobs](/roles/ux-engineer) and [UX engineer salary](/salary/ux-engineer) pages so the template sits next to real reqs.

### UI engineer and UI developer
- Note that “UI developer jobs” is the same cluster as [UI engineer jobs](/roles/ui-engineer) for this board.
- Emphasize implementation quality: responsive layout, states, motion, and the component API.

### Design technologist and design systems engineer
- Design technologist: prototypes and the bridge into engineering. See [design technologist jobs](/roles/design-technologist).
- Design systems engineer: tokens, documentation, multi-brand or multi-platform components. See [design systems engineer jobs](/roles/design-systems-engineer). “Design system jobs” belongs here, not on a separate mechanical page.

### Lines that attract the wrong applicants
- “Design engineer” with no software qualifier.
- Tool lists that are CAD, PCB, or FPGA.
- “Framer” with no mention of the product, which collides with carpentry searches. Say Framer the design tool.

### Before you post
- Use [Post a job](/post-a-job). A standard listing is 30 days.
- Match the public description to the apply page. The hosted text is what gets marked up, and it has to be the real job.
